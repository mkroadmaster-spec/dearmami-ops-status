# 운영대시보드 · 채널 연결 쉬운 가이드

쇼핑몰과 광고 매체를 대시보드에 연결하는 방법입니다. 위에서부터 한 채널씩, 적힌 순서대로만 따라 하면 됩니다. 어려운 부분(데이터 받기, 화면에 올리기)은 Claude 가 대신 합니다. 사람이 할 일은 로그인하고, 값을 복사해서, 정해진 칸에 붙여넣는 것뿐입니다.

> `<내 저장소>` 는 GitHub 저장소 이름(예: `my-company/shop-dashboard`), `<대시보드 주소>` 는 `https://<소유자>.github.io/<저장소>/` 입니다.
> 같은 내용의 HTML 파일(복사 버튼 · 저장소 이름 자동 채움)과 Word 파일도 있습니다. Claude 에게 「채널 연결 가이드 파일을 줘」라고 보내면 됩니다.

## 지켜야 할 것

- 한 번에 한 채널만 합니다. 하나가 끝나면 Claude 에게 「○○ 됐어」라고 보내고 다음으로 넘어갑니다.
- 회색 칸 안의 글자는 그대로 복사해서 붙여넣는 값입니다. 직접 타자로 치지 마세요(오타가 가장 흔한 실패 원인).
- 단, 꺾쇠(< >)나 동그라미(○○)가 들어간 곳은 내 값으로 바꿔야 하는 자리입니다. HTML 파일에서는 맨 위에 저장소 이름을 한 번 적으면 주소가 모두 자동으로 바뀝니다.
- 붙여넣을 때 앞뒤에 빈칸이나 줄바꿈이 들어가면 안 됩니다.
- 화면이 이 설명과 다르게 보이면 그 화면을 캡처해서 Claude 에게 보내세요. 무엇을 누를지 알려줍니다.
- 비밀 값(키·토큰·비밀번호)은 채팅방·메일·메신저에 올리지 않습니다. GitHub 의 Secrets 칸에만 넣습니다.

## 기본 동작 ① 비밀 값 넣기 (모든 채널에서 반복)

1. 아래 주소를 엽니다.
   https://github.com/<내 저장소>/settings/secrets/actions
2. 초록색 **New repository secret** 버튼을 누릅니다.
3. **Name** 칸에 이 가이드의 표에 적힌 이름을 복사해서 붙여넣습니다. (예: `CAFE24_CLIENT_ID`)
4. **Secret** 칸에 매체에서 복사해 온 값을 붙여넣습니다.
5. **Add secret** 을 누릅니다. 값이 여러 개면 2~5번을 반복합니다.

- 저장한 값은 다시 볼 수 없습니다. 틀렸으면 같은 이름으로 한 번 더 저장하면 덮어씁니다.
- 이름은 대문자·밑줄까지 똑같아야 합니다.

## 기본 동작 ② 버튼으로 작업 실행하기 (토큰 발급 때만 사용)

1. 아래 주소를 엽니다.
   https://github.com/<내 저장소>/actions
2. 왼쪽 목록에서 가이드에 적힌 이름(예: **cafe24 authorize url**)을 누릅니다.
3. 오른쪽의 **Run workflow** 버튼을 누릅니다. 가이드가 말한 칸에만 값을 넣고, **나머지 칸(redirect_uri 등)은 건드리지 않고 그대로 둡니다.** 초록색 **Run workflow** 를 한 번 더 누릅니다.
4. 목록 맨 위에 새 줄이 생깁니다(안 보이면 새로고침). 노란 동그라미가 초록 체크로 바뀌면 그 줄을 누릅니다.
5. 열린 화면을 **아래로 내리면** 상자 안에 결과가 있습니다. 링크가 있으면 그 링크를 누릅니다.

- 이 방법은 「접속 허가(토큰) 받기」 때만 씁니다. 데이터 받기와 대시보드 올리기는 Claude 에게 「○○ 됐어」라고 보내면 Claude 가 합니다.
- 빨간 X 로 끝나면 그 줄을 눌러 아래로 내려 보세요. 원인과 해결 방법이 적혀 있습니다. 그 화면을 캡처해 Claude 에게 보내도 됩니다.

## 0. 처음 한 번만 — 저장소 · 저장 공간 · 대시보드 주소

- 걸리는 시간: 20분
- 누가: 대시보드를 관리할 사람 1명
- 준비물: GitHub 계정 (무료, https://github.com 에서 가입) / Claude 에 「운영대시보드」 스킬 설치 — 받은 `ops-dashboard.skill` 파일을 Claude 의 설정 → 스킬 메뉴에서 올립니다. 잘 모르겠으면 Claude 대화창에 그 파일을 붙이고 「이 스킬을 설치해줘」라고 보내세요

### 순서

1. GitHub 에서 빈 저장소를 만듭니다. 아래 주소 → **Repository name** 에 영어 이름(예: `shop-dashboard`) → **Public** 선택 → **Create repository**.
   https://github.com/new
2. Claude 에게 설치를 부탁합니다. 위의 「Claude 에게 보낼 말」 표에서 첫 번째 문장을 복사해 ○○ 만 바꿔 보냅니다.
3. Claude 가 내 저장소에 코드를 올리려면 GitHub 연결이 필요합니다. Claude 가 연결 화면을 띄우면 GitHub 로 로그인하고 1번에서 만든 저장소를 고릅니다.
4. 데이터를 저장할 공간(Neon, 무료)을 만듭니다. 아래 주소 → **Sign up** → GitHub 로 로그인 → **Create project** (이름은 아무거나).
   https://neon.tech
5. Neon 화면의 **Connection string** (`postgresql://` 로 시작하는 긴 글자)을 **Copy** 합니다.
6. 기본 동작 ①로 아래 표의 값 2개를 넣습니다.
   https://github.com/<내 저장소>/settings/secrets/actions
7. 대시보드 주소를 켭니다. 아래 주소 → **Build and deployment** 의 **Source** 를 **GitHub Actions** 로 바꿉니다.
   https://github.com/<내 저장소>/settings/pages
8. Claude 에게 「기본 설정 됐어」라고 보냅니다. 5~10분 뒤 아래 대시보드 주소가 열립니다.
   <대시보드 주소>

### GitHub 에 넣을 값

| Name (그대로 복사) | Secret 에 넣을 값 |
|---|---|
| `DATABASE_URL` | Neon 에서 복사한 Connection string |
| `DASHBOARD_PASSWORD` | 대시보드를 열 때 쓸 비밀번호. 영문·숫자를 섞어 12자 이상으로 직접 정합니다 |

### 다 했으면 Claude 에게

`기본 설정 됐어`

### 잘 됐는지 보는 법

대시보드 주소를 열면 비밀번호 칸이 나오고, 정한 비밀번호를 넣으면 화면이 열립니다. 아직 채널을 연결하지 않았으므로 숫자는 비어 있습니다.

### 막혔을 때

| 이런 일이 생기면 | 이렇게 합니다 |
|---|---|
| 대시보드 주소가 404 로 나온다 | 7번(Pages 설정)을 했는지, 저장소가 Public 인지 확인합니다. 설정 후 첫 배포까지 5~10분 걸립니다. |
| 비밀번호를 넣어도 안 열린다 | DASHBOARD_PASSWORD 를 다시 저장하고 Claude 에게 「대시보드 다시 배포해줘」라고 보냅니다. |

> 대시보드 비밀번호는 짧으면 위험합니다. 주소는 누구나 열 수 있고 비밀번호만이 잠금 장치입니다.

## 1. 카페24 (매출 · 주문 · 방문) — 가장 먼저

- 걸리는 시간: 15분
- 누가: 카페24 쇼핑몰 대표 운영자 계정을 가진 사람
- 준비물: 카페24 쇼핑몰 관리자 로그인 / 몰 아이디 (관리자 주소가 https://○○.cafe24.com 이면 ○○ 부분)

### 순서

1. 카페24 개발자센터에 쇼핑몰 계정으로 로그인합니다. 위쪽 메뉴에서 **Apps(앱 관리)** 로 들어가 **앱 만들기**(또는 「새 앱 만들기」)를 누릅니다(무료). 앱 이름은 아무거나 적습니다(예: `ops-dashboard`).
   https://developers.cafe24.com
2. 만든 앱을 누르면 설정 화면이 열립니다. **권한(Scope)** 항목에서 아래 7개를 모두 체크합니다. 하나라도 빠지면 그 숫자만 빈칸으로 나옵니다: `mall.read_order` `mall.read_customer` `mall.read_community` `mall.read_product` `mall.read_category` `mall.read_application` `mall.read_analytics`
3. 같은 설정 화면의 **Redirect URI** 칸에 대시보드 주소를 붙여넣고 저장합니다: `<대시보드 주소>`
4. 같은 화면에 있는 **Client ID** 와 **Client Secret** 을 복사합니다. 못 찾겠으면 화면을 캡처해 Claude 에게 보내세요.
5. 기본 동작 ①로 아래 표의 값 3개를 넣습니다.
   https://github.com/<내 저장소>/settings/secrets/actions
6. 이제 접속 허가(토큰)를 받습니다. 기본 동작 ②로 **cafe24 authorize url** 을 실행합니다(`mall_id` 칸에 몰 아이디만 입력).
   https://github.com/<내 저장소>/actions/workflows/cafe24-authorize-url.yml
7. 실행이 끝나면 결과 화면 아래쪽의 링크를 엽니다. 카페24 화면에서 **동의** 를 누릅니다. **동의를 누른 순간부터 1분 안에 8번을 끝내야 합니다.** 미리 8번을 읽어 두세요.
8. 대시보드로 돌아오면 화면 아래에 「카페24 인증코드가 도착했습니다」 띠가 뜹니다. **코드 복사** → **token fast 실행 화면 열기** → **Run workflow** → `code` 칸에 붙여넣기 → 초록색 **Run workflow**.

### GitHub 에 넣을 값

| Name (그대로 복사) | Secret 에 넣을 값 |
|---|---|
| `CAFE24_MALL_ID` | 몰 아이디 |
| `CAFE24_CLIENT_ID` | 앱의 Client ID |
| `CAFE24_CLIENT_SECRET` | 앱의 Client Secret |

### 다 했으면 Claude 에게

`카페24 됐어`

### 잘 됐는지 보는 법

Claude 가 과거 데이터를 받은 뒤 대시보드의 「카페24 어드민」 탭에 매출·주문·방문 숫자가 나옵니다. 「채널 연결」 탭의 카페24 카드 2개가 초록색입니다.

### 막혔을 때

| 이런 일이 생기면 | 이렇게 합니다 |
|---|---|
| token fast 가 빨간 X 로 끝난다 (Invalid code · Code time expired) | 1분이 지났거나 코드를 두 번 썼습니다. 6번부터 다시 합니다. 여러 번 해도 괜찮습니다. |
| redirect_uri 오류 | 3번에 넣은 주소와 대시보드 주소가 글자 하나까지 같은지 봅니다(끝의 / 포함). |
| 매출은 나오는데 방문·검색어가 비어 있다 | 2번의 권한 7개 중 `mall.read_analytics` 가 빠졌습니다. 체크한 뒤 6번부터 다시 합니다. |
| 카테고리가 전부 「기타」로 나온다 | Claude 에게 「카테고리가 전부 기타로 나와」라고 보냅니다. 쇼핑몰의 카테고리 이름에 맞춰 다시 분류합니다. |


## 2. 네이버 검색광고 (파워링크 · 플레이스) — 가장 쉬움

- 걸리는 시간: 5분
- 누가: 네이버 검색광고 「광고주」 계정으로 로그인할 수 있는 사람
- 준비물: 네이버 검색광고 광고주 계정 (대행사 계정으로 만든 키는 광고주 데이터를 볼 수 없습니다)

### 순서

1. 네이버 검색광고에 **광고주 계정** 으로 로그인합니다.
   https://searchad.naver.com
2. 광고 시스템 화면 위쪽 메뉴 **도구 → API 사용 관리** 로 들어갑니다. 처음이면 **네이버 검색광고 API 서비스 신청** 을 누릅니다.
3. **액세스라이선스** 와 **비밀키** 를 각각 복사합니다.
4. 화면 오른쪽 위 계정 이름 옆의 숫자(**고객 ID**, CUSTOMER_ID)를 복사합니다.
5. 기본 동작 ①로 아래 표의 값 3개를 넣습니다.
   https://github.com/<내 저장소>/settings/secrets/actions

### GitHub 에 넣을 값

| Name (그대로 복사) | Secret 에 넣을 값 |
|---|---|
| `NAVER_SA_API_KEY` | 액세스라이선스 |
| `NAVER_SA_SECRET_KEY` | 비밀키 |
| `NAVER_SA_CUSTOMER_ID` | 고객 ID (숫자) |

### 다 했으면 Claude 에게

`네이버 검색광고 됐어`

### 잘 됐는지 보는 법

「광고」 탭에 네이버 파워링크(와 플레이스)가 나오고, 「광고 히스토리 → 네이버 검색」에 캠페인·키워드 표가 나옵니다.

### 막혔을 때

| 이런 일이 생기면 | 이렇게 합니다 |
|---|---|
| Auth Failed (403) 가 나온다 | 키를 만든 계정과 고객 ID 가 서로 다른 계정입니다. 광고주 계정으로 로그인해서 그 계정의 키와 고객 ID 를 다시 복사해 3개 모두 다시 저장합니다. |
| 플레이스가 안 나온다 | 플레이스 캠페인이 없으면 나오지 않습니다(정상). |


## 3. 카카오모먼트

- 걸리는 시간: 15분 + 카카오 승인 1~2일
- 누가: 카카오모먼트 광고계정 관리자
- 준비물: 카카오 계정 (광고계정의 멤버) / 카카오모먼트 광고계정 번호 / 사업자등록번호 (비즈 앱으로 바꿀 때 사업자 정보를 묻습니다)

### 순서

1. 카카오 디벨로퍼스에 로그인 → **내 애플리케이션 → 애플리케이션 추가하기**.
   https://developers.kakao.com/console/app
2. 만든 앱을 누르고 왼쪽 메뉴 **앱 설정 → 비즈니스** 에서 **비즈 앱 전환** 을 합니다(사업자 정보 입력).
3. 왼쪽 메뉴 **추가 기능 신청** 에서 **카카오모먼트** 를 신청합니다. 카카오의 승인까지 1~2일 걸립니다. 승인 메일이 오면 다음으로 넘어갑니다.

> 알림이 없으면 데이터가 멈춰도 며칠 동안 모를 수 있습니다. 꼭 연결하는 것을 권합니다.

## 9. 선택 사항 — GA4 · 네이버 데이터랩

- 걸리는 시간: 각 10분
- 누가: 해당 서비스 관리자
- 준비물: GA4 를 쓰는 경우에만 / 경쟁사 검색 추이를 보고 싶은 경우에만

### 순서

1. 이 두 가지는 없어도 대시보드가 동작합니다. 값을 얻는 과정이 길어서 여기에는 넣을 값의 이름만 적었습니다.
2. 연결하려면 Claude 에게 「GA4 연결 가이드를 줘」 또는 「네이버 데이터랩 연결 가이드를 줘」라고 보내세요. 이 문서와 같은 형식으로 한 단계씩 안내합니다. 값을 넣은 뒤에는 「GA4 됐어」 또는 「데이터랩 됐어」라고 보냅니다.
3. 쓰지 않는 메뉴는 숨길 수 있습니다. Claude 에게 「GA4 탭과 경쟁사 탭을 숨겨줘」라고 보내세요.

### GitHub 에 넣을 값

| Name (그대로 복사) | Secret 에 넣을 값 |
|---|---|
| `GA4_PROPERTY_ID` | GA4 속성 ID (숫자만) |
| `GOOGLE_APPLICATION_CREDENTIALS_JSON` | 서비스 계정 JSON 파일 내용 전체 |
| `NAVER_CLIENT_ID` | 네이버 개발자센터 애플리케이션 Client ID (데이터랩 「검색어트렌드」 API 추가) |
| `NAVER_CLIENT_SECRET` | 같은 애플리케이션의 Client Secret |

### 다 했으면 Claude 에게

`GA4 연결 가이드를 줘`

### 잘 됐는지 보는 법

GA4: 「유입·구매 경로(GA4)」 탭이 채워집니다. 데이터랩: 「경쟁사 모니터링」 탭에 검색 추이가 나옵니다.

### 막혔을 때

| 이런 일이 생기면 | 이렇게 합니다 |
|---|---|
| 데이터랩이 401 (Scopes are Empty) 로 실패한다 | 네이버 개발자센터의 그 애플리케이션 → API 설정에서 「데이터랩(검색어트렌드)」를 추가합니다. |


## 연결이 끝난 뒤

- 매일 아침 자동으로 어제까지의 데이터를 받고 대시보드를 새로 올립니다. 사람이 할 일은 없습니다.
- 어제 숫자가 오늘 조금 바뀌는 것은 정상입니다. 광고 매체가 전환을 뒤늦게 확정하기 때문에 최근 3일을 매일 다시 받습니다.
- 대시보드 위쪽에 「⚠ 마지막 데이터 ○일 전」이 보이면 수집이 멈춘 것입니다. Claude 에게 「데이터가 안 들어와」라고 보내세요.
- 채널 하나가 비면 「채널 연결」 탭의 카드 색을 봅니다. 초록 = 정상, 주황 = 일부 실패, 빨강 = 실패, 회색 = 연결 안 함.
- 비밀번호나 키가 다른 사람에게 알려졌으면 그 매체에서 새로 발급해 같은 이름으로 다시 저장합니다.
- GFA·모비온처럼 파일로 올리는 매체는 한 달에 한 번 리포트를 올려 주세요.
